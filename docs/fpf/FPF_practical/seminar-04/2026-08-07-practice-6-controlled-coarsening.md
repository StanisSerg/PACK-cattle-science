# Семинар 4, Практика 6: огрубить формулировку и сохранить возврат к точности

> Задание (слайд 122): взять подробный фрагмент для передачи руководителю для одной названной работы → применить A.6.3.CSC → шестистрочная карточка + короткая фраза.

## Исходная ситуация

- **Подробный фрагмент (X):** method claim метода B «гранулированный допуск + лёгкий протокол сигнала» — `full-cycle/05-method-claim.md` (+ входы: `01-problem-card.md`, `04-method-strategy.md`).
- **Читатель:** руководитель хозяйства (не технолог).
- **Следующая работа:** решить, санкционировать ли 4–6-недельный пилот метода B.
- **Нужный результат:** решение «старт / не старт / вопросы» — не утверждение содержимого метода.

## Восстановление c : X → Y

- **X (точная исходная эпистема):** method claim целиком — забота (цепочка визита замыкается поздно), способ (два связанных правила), роли, применимость с двумя условиями неверности, условия выполнения, намеренный эффект с измерением, границы, честная остановка.
- **Y (точная огрублённая эпистема):** сводка о том же предмете (тот же метод B, та же забота) с содержанием, достаточным только для решения о старте пилота.
- **Связь схем:** каждое утверждение Y восстановимо в X (список допуска → §1.2/§3, сигнал → §1.2/D2, измерение → §1.6, остановка → §1.8).

## Карточка огрубления (шесть строк)

| Строка | Содержание |
|---|---|
| **Содержательная сторона** (Source-bearing side) | `full-cycle/05-method-claim.md` — method claim метода B со всеми секциями (забота, способ, роли, применимость, эффект, границы, остановка) |
| **Короткая форма** (Coarsened rendering) | Сводка ниже — 5 предложений для руководителя |
| **Более узкое использование** (Narrower admissible use) | Решение руководителя: дать добро на старт пилота 4–6 недель (или отказать/запросить детали) |
| **Потеря** (Source-loss mode) | Классификация действий по цене ошибки; два условия неверности метода; пороги способностей помощников; метрики приёмки (доля визитов, медианное время); границы (масштаб >2–3 хозяйств, мотивация); состав пробелов D1–D4 |
| **Неподдерживаемое усиление** (Non-admissible downstream use) | По сводке НЕЛЬЗЯ: утверждать список допуска D1; оценивать риск ошибочных действий помощника; менять метод; судить об эффекте после пилота; переносить на другое хозяйство |
| **Условие возврата** (Reopen trigger) | Вопрос «а что если помощник ошибётся?»; утверждение списка допуска; разбор итогов пилота (нед. 4–6); любой спор о продолжении/остановке |

## Короткая форма (для руководителя)

> Помощники на визитах начнут сразу делать мелкие безопасные изменения сами, а всё дорогое — только после вашего подтверждения в тот же день. После каждого визита вы получаете сигнал из трёх строк: «был / сделал сам / ждёт подтверждения». Пилот на 4–6 недель: меряем долю изменений, выполненных в день визита — не выросла, останавливаемся и разбираемся, а не усиливаем. От вас нужно добро и один час на утверждение списка «что можно делать самим».

## Проверка по диагонали (слайд 122)

- Потеря названа явно? Да — пятая строка карточки.
- Тот же предмет? Да — сводка о методе B, не о «проекте улучшений вообще».
- Закрыт правдоподобный более сильный вывод? Да — сводка не поддерживает утверждение списка допуска и оценку рисков (самый вероятный неправильный вывод руководителя: «раз безопасно — пусть делают всё сами»).
- Это не просто краткий пересказ? Область использования сужена до одного решения (старт пилота), остальные использования явно заблокированы.

## Что узнали (carry-through)

- Главная потеря, которую стоило назвать явно, — **классификация по цене ошибки**: именно она отличает метод от «разрешить помощникам самостоятельность». Без неё сводка читается как «помощники делают что хотят».
- Условие возврата оказалось практичным триггером: вопрос руководителя «а если ошибётся?» — это не возражение, а сигнал открыть X на секции §1.2/§3 (список допуска).
- Связка с С4-П2 (E.17): сводка для руководителя и D2 для помощника — два описания одного метода (A.3.2); следующая практика строится на этом же X.
