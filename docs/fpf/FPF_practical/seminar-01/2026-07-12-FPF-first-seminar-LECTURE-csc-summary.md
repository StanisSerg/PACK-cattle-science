## Короткая форма

**FPF** — язык паттернов, связывающий реальность, знания и работу; цель — первый полезный результат, открывающий ранее невозможный рабочий ход. Окупается в коллективной передаваемой работе, избыточен для разовых пятиминутных задач.

**Три уровня:** FPF (общая онтология, авторы фреймворка) → DPF (предметные паттерны, эксперты области) → LPF (местные правила предприятия). DPF/LPF пишутся на языке FPF и не могут нарушать его онтологию. DRR — инструмент автора DPF/LPF, не часть FPF.

**Карточка README ≠ паттерн ≠ мантра.** Карточка — вход для пользователя (узнать ситуацию). Паттерн — ядро (Problem frame, Forces, Solution, Consequences). Мантра — учебная развёртка внутри карточки, не план работы.

**Паттерны — не цепочка.** Следующий паттерн выбирается по соответствию ситуации его Problem frame, порядок управляется ограничениями CGUS, а не линейным сценарием; шаги можно пропускать и возвращаться.

**Kind и эпистема.** Kind = интенсионал + экстенсионал + отношения. Эпистема — kind знаний (граф утверждений об интересующей сущности); файл/экран — лишь носитель публикации.

**Архитектура ≠ описание ≠ математика.** Архитектура — реальные структуры (`U.System`), описание и модели — эпистемы. АрхГейт — не архитектура, а метод оценки архитектурных решений по 7 характеристикам ЭМОГССБ.

**EOC и bounded context.** EOC — объект текущего рассуждения. Слово без контекста плавает: «кетоз» — BHB ≥ 1.2 ммоль/л (ветеринарный), событие потерь (экономический), негативный энергетический баланс (рациональный), фактор отбора (племенной).

**Акаузальность.** FPF — набор ограничений, а не рецепт; агент предлагает подходящий паттерн, человек проверяет и выбирает.

**Минимальная онтология — 12 понятий:** EOC, Holon, Episteme, Method, WorkPlan, Work, Structure, Architecture, Characteristic, Candidate, Decision, Role.

**C22.2 — карточка проблемы.** Слабый сигнал → `ProblemCard@Context`: наблюдаемый сигнал, ограниченный контекст, граница принятой проблемы, признак улучшения, следующее использование. Пример: pH мочи группы А 6.8 при целевом 6.0–6.5 (анионная диета, МТК Ленинский, июль 2026).

**Изменения рабочих ходов (E.18.1):** (1) «результат» → состояние до/после (`affectedReferent`, `preState`, `postState`/`delta`, `outcome`); (2) разбор → capture-файл на диске; (3) паттерн → обязательное применение к проекту; (4) ProblemCard перед любым кодом (WP-107); (5) три уровня README (FPF-README, GitHub README, локальный README.md).
