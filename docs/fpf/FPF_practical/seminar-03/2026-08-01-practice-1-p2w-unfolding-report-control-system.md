# Практика 1 (семинар 3): длинная P2W-развёртка проекта «Система контроля отчётов технологов»

> Практикум 1 семинара 3 (слайд 26): восстановить длинную P2W-развёртку своего проекта.
> Рамка: карта выражает **зависимость результатов, а не очередь работ** (мантра ≠ план).
> Источники: семинар 1 (метод обучения, пилот с технологом), семинар 2 (OPTION-COMPARISON → probe B; граница системы; ProblemCard межуровневого конфликта; план пилота B; пример CASE-002), ответы пилота 2026-08-01.

## Принятая проблема (формулировка пилота)

Цепочка «отчёт → прочтение → решение → действие» разорвана: компании несколько раз внедряли систему отчётов технологов, но руководство отчёты не читает, действий не происходит → технологи перестали писать. Отчётность деградировала до «пишем и ждём указаний ведущих технологов»; ведущие заняты → свалка информации.

**Различение семинара 3:** это «работа равна нулю» — отчёт написан (усилие было), а преобразования не произошло. Прямая иллюстрация capture «сделал, но не донёс до системы» (WP-98, 2026-07-31).

| 9 | Работа участвует в преобразовании | Учёт ведётся; связь «сводка → вмешательство/ответ технологу» не установлена (эпизодическая) | 🔴 |

**Красные ветки:** нет пригодного метода → к стратегированию; не готово → подготовить ресурсы / build-the-builder; изменение не подтверждено → диагностировать метод, выполнение, причинную гипотезу.

## Первый разрыв (место входа)

**Позиции 7–8: нет готовой системы-исполнителя.** Метод есть, поток отчётов есть, план есть — но работу выполняет пилот вручную. Нужен механизм, при котором это делают помощники. Для этого сначала надо описать сами потоки (критерий позиции 2): кто, куда, что, как обрабатывается.

## Первый вопрос для FPF (дисциплина E.18.1)

> «Как описать потоки отчётов технологов (кто пишет, куда, какую информацию, как она обрабатывается и используется) так, чтобы метод “сводка → кейс → учёт → вмешательство” могли выполнять помощники без участия пилота?»

Кандидаты-карточки: «Написать рабочие правила, метод или процесс» (METHOD-PROCESS, семинар 1); описание потока таблицей позиций (практикум 4 семинара 3, слайд 147).
