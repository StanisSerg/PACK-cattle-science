# Суть разговора

Разговор ведётся в контексте практического курса FPF. Обсуждается, как правильно работать с AI-агентами: как собирать intake, какой он должен быть длины, как использовать FPF-карточки и как сохранять контекст между сессиями.

## 1. Уровни работы с FPF

FPF можно использовать по-разному: от «Мурки одним пальцем» до полноценного концерта. AI-агент сам вытаскивает мантру из README и пытается обратить внимание на другие ходы. Чтобы управлять его вниманием, можно явно указать на карточку README или сказать: «дай мне все поля nameCard по F.18 и выполни полную процедуру». Иначе агент интуитивно заполнит 3-4 поля и вернёт ответ.

## 2. Intake — это не просто промпт

Intake включает промпт, файлы, ссылки, предварительные тексты, разговоры из других чатов. Это задача сотруднику, а не пустые уговоры. В практикумах используется одна фраза, но в реальности intake должен быть длинным — страницы текста с примерами, граундингом, типизацией, неизвестностями.

## 3. Пример использования FPF для выявления архитектурных характеристик

Ainur привёл пример с запуском биллинга. FPF выделил характеристику «богатство» бизнесов в срезах. Через полгода новый срез оказался богатым, и это могло сломать проект. FPF помог заранее увидеть, что добавление нового среза — не просто «новое значение enum».

## 4. Проблема синтетических примеров

Джавархарлал отмечает, что быстрые синтетические intake типа «помоги выучить английский» — это сжигание токенов без следующего хода. Нужны реальные проекты, в которых результат важен.

## 5. Шеринг чатов-сессий и сохранение контекста

Ainur спрашивает, как шерить сессии с агентами между коллегами. Идея — внешний цифровой двойник сессии, в котором несколько людей могут контрибьютить, а артефакты пересобираются автоматически. Сейчас он решает вручную: вспоминает, что было в чате Б, и просит собрать документ.

## 6. Практика от Dmitry Nik

- Intake: несколько предложений как формулировка задачи агенту + ссылки на материалы проекта.
- Агент работает в контексте проекта, дополняет поиском.
- Результаты сохраняются в проект.
- Инструменты: VS Code + OpenCode + Deepseek4 Pro + Socraticode (семантический поиск) + project-vault (https://github.com/dimonier/skills/tree/main/skills/project-vault).
- Сохранять результаты работы в файл — промежуточный или конечный продукт, артефакт или отчёт. Тогда агент в следующий раз увидит результаты своего прошлого труда.
