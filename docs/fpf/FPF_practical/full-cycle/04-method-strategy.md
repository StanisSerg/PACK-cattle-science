# 04 — Стратегирование метода: своевременное замыкание цикла визита

> Вход: `01-problem-card.md`, `03-interlevel-conflict.md` (К1, К2 — как защищаемые размены, не сводимые к одному баллу).
> Факты не выдуманы; непроверенное помечено «пробел».

## 1. Сигнатура искомого метода

- **Предмет метода:** цепочка «визит помощника → информация у ведущего → изменения на ферме».
- **Конечное состояние:** изменения, требуемые в день визита, выполнены в день визита — при нагрузке помощника на сообщение ≤ 2–3 минут и без потери контроля ведущего над дорогими действиями.
- **Название операции:** своевременное замыкание цикла визита.

## 2. Методы-кандидаты (три разных типа)

| # | Тип | Кандидат | Суть |
|---|-----|----------|------|
| A | Обучение людей | **Наставничество помощников** | Обучение «что сообщать и как действовать в типовых ситуациях» через разборы и совместные визиты, без формальных правил |
| B | Изменение процесса | **Гранулированный допуск + лёгкий протокол сигнала** | Письменное правило: список действий «делай сам» / «только с подтверждением» + формат сообщения «сигнал сразу (≤2 мин), подробности позже» |
| C | Автоматизация | **Бот-форма отчёта в Telegram** | Структурированный отчёт кнопками (визит завершён / сделал X по правилу / нужен ответ), автонапоминание и эскалация при тишине |

## 3. Пространство характеристик (A.19.ECS)

- **Оцениваемый kind:** метод-кандидат для замыкания цикла визита.
- **Область использования:** один выбор метода для хозяйства в РБ, 1 ведущий + 2 помощника, Telegram.
- **Защищаемые размены:** К1 (нагрузка помощника) и К2 (риск ошибки без второго чтения) — не агрегируются в общий балл.
- **Правило пропусков:** неизвестное = «пробел», не оценка.

| Характеристика | Шкала | Значение шкалы |
|---|---|---|
| Х1. Срок до работающего метода | дней | меньше = лучше |
| Х2. Нагрузка помощника на сообщение | минуты | меньше = лучше (К1) |
| Х3. Закрывает разрыв полномочий | нет / частично / гранулированно | (К2) |
| Х4. Риск ошибки без второго чтения | низкий / средний / высокий | (К2) |
| Х5. Стоимость поддержки | часы ведущего в месяц | меньше = лучше |
| Х6. Масштабируемость (больше хозяйств/помощников) | низкая / средняя / высокая | |

## 4. Сравнение

| Х | A (наставничество) | B (допуск+протокол) | C (бот-форма) |
|---|---|---|---|
| Х1 | 14–30 | 5–10 | 30–60 (разработка/настройка) |
| Х2 | не снижает (пробел: 5–10 мин останется) | ≤2–3 | ≤1–2 |
| Х3 | нет (учит, но не даёт права) | гранулированно | нет сам по себе — требует B внутри |
| Х4 | средний (зависит от усвоения) | средний (зависит от качества списка допуска) | средний |
| Х5 | высокая (регулярные разборы) | низкая (ревизия правил ~раз в квартал) | средняя (поддержка бота) |
| Х6 | низкая (привязана к людям) | высокая (документ) | высокая |

**Недоминируемые кандидаты:**
- **B** — лучший по сроку и закрытию К2, проигрывает C по Х2 и A по развитию компетенций.
- **C** — лучший по Х2, но долог и без B не решает К2 (форма без допуска = быстрые «что делать?» вместо «сделал X»).
- **A** — проигрывает B по всем координатам, кроме развития суждения помощника вне списка (ниша-дополнение, не замена).

A и C не отбрасываются: A остаётся фоновым дополнением, C — кандидатом усиления при провале или масштабировании B.

## 5. Рекомендация (C.11): наименее худший — B

**Выбор: B (гранулированный допуск + лёгкий протокол сигнала).**

**Инженерное обоснование:**
- Единственный кандидат, закрывающий оба конфликта одновременно: лёгкий формат снимает К1 (≤2–3 мин), гранулированный допуск снимает К2 (дешёвые действия — сам, дорогие — с подтверждением).
- Самый быстрый (5–10 дней: документ + согласование с помощниками) и самый дешёвый в поддержке.
- C не выбираем сейчас: он реализует тот же протокол, но за 30–60 дней и без допуска внутри не решает К2; его место — усиление B позже (форма «кнопками» поверх работающего правила).
- A не выбираем как основной: обучение без допуска не даёт помощнику права действовать — цикл в моменте не замыкается.

**Условия, при которых выбор НЕВЕРЕН (явные):**
1. **Цена ошибки высока по большинству «моментных» изменений** → гранулированный допуск невозможен, B неверен; нужен метод «обязательное второе чтение» (усиление канала, не допуска) — это другой баланс К2.
2. **Задержка вызвана не форматом, а мотивацией помощников** (не пишут, потому что «не их дело») → ни B, ни C не помогут; проблема управления, а не метода — возврат к карточке проблемы.
3. **Масштаб вырастет** (больше хозяйств/помощников) → C становится основным раньше срока; B остаётся как регламент внутри C.

**Пробелы (блокируют детализацию, не выбор):**
1. Классификация «моментных» изменений по цене ошибки (вход для списка допуска — шаг 05, делать пилотом).
2. Готовность помощников к допуску (не спросили).
3. Фактический срок, за который помощник реально пишет сейчас (проверка Х2 в пилоте).

## Проверка выбора в пилоте

Критерий приёмки из карточки проблемы: доля визитов с выполненными в день изменениями и медианное время «визит → изменение». Замер до внедрения B (базовая линия) и через 4–6 недель после. Если движения нет — красная ветка «изменение не подтверждено»: диагностировать метод, выполнение, причинную гипотезу.
