# 07 — Потоки применения и создания

> Вход: `02-system-boundary.md` (система), `05-method-claim.md` (метод).
> Это не календарный план, а отношение создания и использования одного холона.

## 1. Поток применения: «визит завершён → изменение выполнено на ферме»

| # | Позиция | Вход | Выход | Допустимое преобразование (A.3.4) |
|---|---------|------|-------|-----------------------------------|
| 1 | Классификация по допуску | Наблюдения визита + список допуска (D1) | Каждое нужное изменение отнесено: «сам» / «с подтверждением» | Только классы из D1; неизвестное действие → «с подтверждением» |
| 2a | Действие «делай сам» (ветвь 1) | Изменения класса «сам» | Изменение выполнено помощником/персоналом на месте | Только действия из списка допуска, без превышения |
| 2b | Сигнал отправлен | Визит завершён + итог классификации | Сообщение ≤2–3 мин: «визит был / сделал сам: … / ждёт подтверждения: …» | Форма D2; подробности — отдельно, позже в тот же день |
| 3 | Подтверждение ведущего (ветвь 2) | Пункт «ждёт подтверждения» | Решение ведущего: да / нет / уточнение — в тот же день | Ответ в окне подтверждений; тишина → правило эскалации D3 |
| 4 | Изменение выполнено на ферме (соединение) | Ветвь 1 (уже сделано) ИЛИ ветвь 2 (по решению ведущего) | Состояние фермы изменено в день визита | Выполнение персоналом/помощником по решению; запись в журнал |

Ветвление — на позиции 1 (по классам допуска); соединение — на позиции 4 (оба пути заканчиваются выполненным изменением или явным «не делаем с записью причины»).

## 2. Поток создания/изменения системы (build the builder)

| # | Позиция | Вход | Выход |
|---|---------|------|-------|
| 1 | Список допуска v1 | Решение внедрить метод B + знание цены ошибки (пилот) | D1: классы «сам»/«с подтверждением» |
| 2 | Протокол и инструктаж | D1 + форма сигнала (D2) + эскалация (D3) | Помощники ознакомлены, окно подтверждений задано |
| 3 | Пилот метода | Стартовая дата | 4–6 недель работы по методу, журнал в Telegram |
| 4 | Замер и разбор | Журнал + базовая линия | Доля в-срок, медиана, разбор эпизодов сбоев |
| 5 | Ревизия | Итоги разбора | Список допуска v2 (и при необходимости форма сигнала v2) |

## 3. Связь потоков (A.12)

Система обмена визитной информацией в потоке создания — **создаваемый предмет** (её устройство меняется: список допуска, форма сигнала, правила). В потоке применения та же система — **преобразователь** (TransformerRole): именно она превращает «визит завершён» в «изменение выполнено на ферме».

Артефакты потока создания (D1 список допуска, D2 форма сигнала, D3 эскалация) — не документы рядом с системой, а **эпистемные части самой системы**: без них поток применения разрешается в «сделал — не сделал» по настроению. Ревизия (позиция 5) — момент, где поток применения возвращает фактуру в поток создания: эпизоды сбоев меняют список допуска.

## 5. Решения пилота 2026-09-05 (D1–D3)

### D1 — список допуска v1

| Помощник (Ник) делает сам в рамках визита | Только с согласования ведущего технолога |
|---|---|
| Корректировки по сухому веществу (на основе замеров СВ) | Увеличение/уменьшение концентратов в рационе |
| Вопросы группировки | Все прочие действия — по умолчанию сюда |
| Рекомендации | |
| Корректировка дозировки анионных солей | |

Форма согласования: звонок ведущему технологу + дублирование записи в Telegram.

Дополнение: ведущий технолог может заранее выдать полномочия по конкретному хозяйству — они расширяют список «делай сам» для этого хозяйства.

### D2 — форма записи и протокол подтверждения

Форма сигнала утверждена как есть: «визит был / сделал сам: … / ждёт подтверждения: …» (≤2–3 минуты, подробности — отдельно, в тот же день).

Форма записи «выполнено» — сообщение в Telegram.

Протокол для действий «с подтверждением»:
1. Помощник считает нужным изменение → звонок ведущему технологу.
2. Согласовано → выполняет сразу + запись в Telegram («сделали …»).
3. Ведущий не отвечает → запись в Telegram, но **не выполняет** до ответа.
4. Есть заранее выданные полномочия по хозяйству → выполняет сразу, запись в Telegram обязательна.
5. Нет полномочий и нет ответа → не выполняет; при ответе в течение дня — выполняет после ответа.

### D3 — граница «тот же день», окно, эскалация

- **Граница «тот же день»:** до 23:59 календарного дня.
- **Окно подтверждений ведущего:** 8:30–18:00.
- **Эскалация при тишине:** в конце дня помощник повторяет сообщение (❗) и звонит ещё раз; изменение не выполняется и переносится на следующий день с записью причины.
