# 05 — Method claim: своевременное замыкание цикла визита

> Вход: выбор метода B (`04-method-strategy.md`). Обязательства паттернов — из корпуса FPF (query_fpf_spec, proof, 2026-08-02):
> `A.3.1` — метод = воспроизводимый способ действия **с явной применимостью**; не путать с описанием, планом, выполненной работой, назначением роли.
> `A.3.2` — описание = эпистема об одном admitted-методе; несколько описаний одного метода допустимы, у каждого своя аудитория; пороги способностей — отдельно (A.2.2).

## 1. Method claim (A.3.1)

### 1.1. Забота метода (concern)

Цепочка «визит помощника → информация у ведущего → изменения на ферме» замыкается слишком поздно: изменения, требуемые в день визита, не выполняются в день визита.

### 1.2. Способ (way of doing)

Два связанных правила, применяемые вместе на каждом визите:

1. **Гранулированный допуск:** каждое «моментное» изменение заранее отнесено к одному из двух классов — «помощник делает сам» / «только с подтверждением ведущего». Класс определён ценой ошибки действия.
2. **Лёгкий протокол сигнала:** после каждого визита помощник отправляет сообщение по форме «сигнал сразу» (≤2–3 минут: визит был, что сделал сам, что ждёт подтверждения), подробности — отдельно и позже в тот же день.

### 1.3. Участники и их роли

| Участник | Роль в методе |
|---|---|
| Помощник | Исполнитель визита; действует в рамках допуска; отправляет сигнал по форме |
| Ведущий технолог | Держатель списка допуска; подтверждает/отклоняет дорогие действия; ревизует правила |
| Персонал фермы | Физический исполнитель части изменений по указанию помощника/ведущего |

Пороги способностей (A.2.2): какой помощник допускается к какому классу действий — **пробел** (требует решения пилота: сразу все или поэтапно).

### 1.4. Применимость (applicability)

Хозяйство в РБ; визиты помощников по расписанию; канал — Telegram; наличие ведущего технолога, способного отвечать в тот же день. Метод **не применим**: при высокой цене ошибки большинства «моментных» изменений (условие неверности 1 из шага 04), при отсутствии мотивации помощников (условие неверности 2).

### 1.5. Условия выполнения (conditions)

- Список допуска записан и подтверждён ведущим (содержимое — **пробел**, делает пилот).
- Помощники ознакомлены со списком и формой сигнала (одна встреча-инструктаж).
- Ведущий доступен для подтверждений в согласованное окно дня.

### 1.6. Намеренный эффект (intended effect)

Изменения класса «делай сам» выполняются в день визита без участия ведущего; изменения класса «с подтверждением» получают решение в тот же день. Измерение: доля визитов с выполненными в-срок изменениями; медианное время «визит → изменение» (приёмка по карточке проблемы).

### 1.7. Границы (bounds)

Метод не решает: качество самих решений об изменениях (предметная компетентность), мотивацию помощников, масштаб >2–3 хозяйств (там кандидат C — бот-форма поверх этого же регламента).

### 1.8. Ближайшая остановка (honest stop)

Если через 4–6 недель пилота доля своевременных изменений не растёт — остановка и диагностика: метод (список допуска неверен), выполнение (сигнал не отправляется), причинная гипотеза (задержка была не от формы, а от мотивации). Не «усиливать» метод автоматически.

## 2. Необходимые MethodDescription (A.3.2)

Одного метода — несколько описаний, по аудиториям:

| # | Описание | Аудитория | Назначение | Статус |
|---|----------|-----------|-----------|--------|
| D1 | **Список допуска** (классы действий, цена ошибки, примеры) | помощник | что делать самому, что подтверждать | пробел — содержимое у пилота |
| D2 | **Карточка сигнала** (форма «сигнал сразу»: 3 строки, ≤2 минут; примеры) | помощник | как сообщать после визита | можно собрать следующим шагом |
| D3 | **Правило подтверждений** (окно ответа ведущего, эскалация при тишине, что считать «не подтверждено») | ведущий | дисциплина ответа в тот же день | пробел |
| D4 | **Инструкция для персонала фермы** (кто из помощников что вправе назначать) | персонал фермы | принимать указания помощника в рамках допуска | пробел |

Общее ограничение A.3.2: все четыре описания — об **одном** методе (одна забота, один способ); противоречия между ними — дефект редакции, не «разные методы».

## 3. Пробелы до передачи метода

1. **Классификация «моментных» изменений по цене ошибки** — содержимое D1; делает пилот (знает ферму).
2. **Формат «сигнала сразу»** — 3 строки: «визит был / сделал сам: … / ждёт подтверждения: …» — кандидат, утвердить пилоту.
3. **Правило эскалации при тишине** — если ведущий не ответил к [часу], что делает помощник (действие по умолчанию: ничего / безопасный вариант / повторный сигнал)?
4. **Пороги способностей помощников** — допуск сразу полный или поэтапный?
