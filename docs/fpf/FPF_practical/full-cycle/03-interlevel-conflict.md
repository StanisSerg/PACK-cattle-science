# 03 — Межуровневый конфликт: допуск помощника и нагрузка канала

> Паттерн: `B.2` (Meta-Holon Transition). Вход: `02-system-boundary.md`; симптом — отсутствующее правило допуска, разрыв полномочий.
> Вопрос шага: есть ли локально разумные изменения внутри системы, которые вредят другому уровню? Ответ: **есть, два связанных.**

## Уровни раскладки

- **Уровень +1 (целое):** хозяйство / ферма — продуктивность, риск вмешательств.
- **Уровень 0 (система):** обмен визитной информацией (помощники + канал + ведущий) — своевременность изменений.
- **Уровень −1 (части):** помощник, ведущий — время, тревога, ответственность.

## Конфликт К1: полнота и скорость информирования ↔ нагрузка помощника

**Локально разумное изменение (уровень 0):** требовать от помощника подробное сообщение сразу после визита — цикл «визит → информация → действие» замыкается в тот же день.

**Что теряет уровень −1 (помощник):** время и внимание. Подробное сообщение сразу после визита — это минуты, которых нет (дорога, следующий визит, личные дела). Чем полнее формат, тем позже он реально отправляется: требование «пиши сразу и подробно» порождает откладывание — система получает задержку, от которой хотела уйти.

**Форма конфликта:** полнота+своевременность данных для системы ↔ рабочая нагрузка и тревога помощника. Прямой аналог конфликта «полнота данных ↔ время технолога» из практики 2 семинара 2.

**Следствие для метода (шаг 04):** формат сообщения должен иметь потолок труда (например, ≤2–3 минут на сообщение) и разделять «сигнал сразу» / «подробности позже» — иначе К1 съест любой метод.

## Конфликт К2: своевременность вмешательств ↔ риск ошибки и контроль ведущего

**Локально разумное изменение (уровень 0):** ввести правило допуска — помощник выполняет согласованный список изменений в моменте, без звонка ведущему.

**Что теряет уровень +1 (хозяйство/ферма):** защиту от ошибочного вмешательства. Расширенный допуск помощника = вероятность неверной корректировки (рациона, ветеринарного действия) без второго чтения; цена ошибки на ферме выше цены задержки по части вопросов.

**Что теряет уровень −1 (ведущий):** контроль и привычную картину «всё через меня»; для помощника — рост ответственности без роста оплаты/статуса (возможное сопротивление).

**Форма конфликта:** скорость изменений для фермы ↔ риск ошибки без второго чтения + граница ответственности между ведущим и помощником.

**Следствие для метода (шаг 04):** допуск нужен **гранулированный** — список действий, которые помощник делает сам (низкая цена ошибки), и список «только с подтверждением» (высокая цена ошибки). «Всё делать самому» и «всё спрашивать» — оба проигрышных полюса К2.

## Что конфликтом НЕ является

- Сам разрыв полномочий — это дефект устройства системы (отсутствующая часть), а не конфликт уровней; конфликт начинается при попытке его лечить.
- Задержка сообщений сама по себе — не конфликт, а симптом К1 (формат слишком тяжёл для «сразу»).

## Связь двух конфликтов

К1 и К2 делят один рычаг: чем больше допуск у помощника (К2 в сторону скорости), тем легче сообщение «сделал X по правилу» вместо «что делать?» (К1 в сторону меньшей нагрузки). Метод, который соберёт гранулированный допуск + лёгкий формат сигнала, гасит оба конфликта одновременно. Это кандидат в критерии сравнения методов на шаге 04.

## Явные пробелы

1. Цена ошибки по типам изменений: какие «моментные» изменения обратимы/дешевы, какие — нет? (вход для грануляции допуска)
2. Реальный бюджет времени помощника на сообщение (минуты)?
3. Готовность помощников к расширенной ответственности — хотят ли её?
