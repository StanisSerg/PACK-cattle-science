# Практика 4 (семинар 3): поток работ и изменений таблицей позиций — условное хозяйство Беларуси

> Практикум 4 семинара 3 (слайд 147): описать небольшой поток таблицей из 3–5 существенных позиций,
> показать ветвление/соединение, для одной намеченной работы назвать готовое и недостающее.
> Формат таблицы — по слайду 145 (раздел 15 «Письменные формы помогают совместно проектировать поток»).
> Объект: условное хозяйство Беларуси (КТ Зенченко не показательно — Казахстан).

## Поток одной фразой

**«Еженедельный замер технолога при посещении хозяйства → внесение данных в систему → корректировка рациона на месте → согласование с зоотехником хозяйства → внедрение и запись результата»**.

**Место в большой P2W** (см. `2026-08-01-practice-1-p2w-unfolding-report-control-system.md`): позиции 8–9 развёртки; поток лечит позицию 7 (готовность) — превращает блокнот в систему-исполнителя. Итоговое изменение большого проекта: цепочка «замер → данные → действие» замыкается в тот же визит, без ведущего технолога в рутине.

## Фактура (от пилота, 2026-08-01)

- Отчёт = замер при посещении: СВ, Пенсильванские сита, навозные сита, жвачка, молоко из компьютера, реализация из журнала. Ритм: раз в неделю (индивидуально 2/нед – 1/2 нед).
- Сейчас данные фиксируются в блокноте и часто не доходят до программ («измерял, в блокнотике; в TWR-трекер не ввёл») — миниатюра принятой проблемы: работа равна нулю.
- Роли: ведущий технолог (пилот) — основной рацион; технологи (помощники) — корректировки на месте по СВ/ситам; зоотехник хозяйства — согласование внедрения.
- Внесение данных — в два приёмника: программа расчёта рациона (АМТС) — критично в момент визита (данные оттуда для отчёта не вытянуть); markdown-запись кейса — для анализа агентами и отчётов, можно в течение недели.

## Таблица позиций (v3)

| # | Позиция | Что рассматривается | С чем связано | Какая работа/ветвь зависит |
|---|---------|--------------------|--------------|---------------------------|
| 1 | **Замер технолога** | СВ, Пенсильванские сита, навозные сита, жвачка, молоко из компьютера, реализация из журнала | → поз. 2 | Весь поток: нет замера — нечего вносить |
| 2 | **Внесение данных — разветвление на два приёмника** | Одни данные — в два места: потребители разные, из АМТС для отчёта не вытянуть | ← поз. 1 | Риск: двойное внесение → рассинхрон |
| 2a | **→ АМТС (программа расчёта рациона)** | Технолог вносит данные, корректирует, сохраняет рацион. **Критично в момент посещения** | ← поз. 2; → поз. 3 | Без этого корректировка — по памяти |
| 2b | **→ Markdown-запись кейса хозяйства** | Данные для анализа агентами и отчётов. **Не критично в момент визита — до конца недели** | ← поз. 2; → поз. 6 | Без этого нет аналитики и отчётов |
| 3 | **Корректировка рациона на месте** | По СВ и ситам, в рамках основного рациона ведущего технолога | ← поз. 2a; → поз. 4 | **Ветвление A:** выход за рамки основного рациона → эскалация ведущему технологу |
| 4 | **Согласование с зоотехником** | Утверждение корректировки для внедрения | ← поз. 3; → поз. 5 | **Ветвление B:** не согласовано → возврат к поз. 3 |
| 5 | **Внедрение + запись результата** | Новый рацион в работе; результат — следующим замером | ← поз. 4; назад к поз. 1 | Замыкание цикла; значения до/после (поз. 10–11 большой P2W) |
| 6 | **Отчёт по хозяйству** | Агент анализирует markdown-архив кейса → отчёт | ← поз. 2b | Связь потока с отчётностью большого проекта |

**Следствие из разной срочности:** 2a — обязательная часть визита (проверяется до отъезда), 2b — делегируемая работа внутри недели. Снимает возражение «двойная нагрузка на технолога».

**Риск двойного внесения** (АМТС ↔ markdown) → чек-лист визита (слайд 146): «данные внесены в АМТС, рацион сохранён» — до отъезда; «markdown-запись создана» — до конца недели. Перспектива build-the-builder: генерировать markdown из структурированной формы (отдельная P2W).

**Kind/паттерн (по правилу практикума — только обоснованное):** U.Transfer — передача данных замера (поз. 1→2); E.18 — структура потока целиком. Остальное — пробел.

## Намеченная работа: «внесение данных при посещении» (поз. 2a + 2b)

- **Готово:** состав показателей; функция внесения в АМТС; ритм визитов; markdown-формат кейсов (отработан на CASE-002).
- **Не хватает (следующий ход проекта — отдельная работа, не практикум):** правило «2a — до отъезда, 2b — до конца недели» как записанный метод; чек-лист визита; markdown-шаблон замера; договорённости с технологами.

## Применение FPF: полный проход A.3.1 / A.3.2 (через MCP)

Затруднение из таблицы: «как написать метод так, чтобы помощники выполняли его без пилота» → открыты паттерны **A.3.1 U.Method** и **A.3.2 U.MethodDescription**, Solution применён к хозяйству.

**Обязательства A.3.1:** идентичность метода = participant meanings (kind'ы ролей, не люди) + applicability + conditions + intended effect + bounds. Три независимости: description-independent (метод ≠ инструкция), run-independent (метод ≠ конкретный визит), assignment-independent (метод ≠ «Вася делает» — это A.2/A.15).

**Эскиз method claim (не утверждённый метод):**

> **Метод «Замер и внесение данных при посещении»**
> - **Способ:** при посещении технолог выполняет замер (СВ, сита Пенсильванские и навозные, жвачка, молоко из компьютера, реализация из журнала) и вносит данные в два приёмника: АМТС — до отъезда; markdown-запись кейса — до конца недели.
> - **Применимость:** хозяйства на сопровождении с визитами технолога; корректировки в рамках основного рациона ведущего технолога.
> - **Условия:** основной рацион существует; АМТС доступна на месте; markdown-шаблон опубликован.
> - **Намеренный эффект:** данные сохранены в системе, рацион скорректирован в день визита — цепочка «замер → данные → корректировка» замыкается без ведущего технолога в рутине.
> - **Границы:** выход за рамки основного рациона → эскалация (ветвление A).
> - **Ближайшая остановка** (local method mantra): АМТС недоступна / данные неполные → стоп, markdown-фиксация «неполный замер», уведомление ведущего.

**A.3.2:** чек-лист визита, markdown-шаблон, инструкция АМТС — это описания (эпистемы) метода, а не сам метод; один метод → несколько описаний. Разведение бесплатно: «обучить технологов до конца августа» — U.WorkPlan (A.15.2); конкретный визит — U.Work (A.15.1).
