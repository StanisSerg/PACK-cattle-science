## Разбор перехода 4→5 (по шаблону слайда 157)

- **Что уже известно:** метод B апробирован вручную (CASE-002); состав показателей замера; поток описан (таблица v3, практика 4); эскиз method claim по A.3.1 (практика 4, секция «Применение FPF»).
- **Какой предмет/отношение надо получить:** утверждённый **U.Method** «Замер и внесение данных при посещении» + его **U.MethodDescription** (чек-лист визита, markdown-шаблон замера) + договорённость с технологами.
- **Какая следующая работа предусмотрена большой P2W:** поз. 7 (готовность, full kit) → поз. 8 (система выполняет работу — технологи вместо пилота).
- **Почему ей нужен этот результат:** без переданного метода исполнитель = пилот; работа не масштабируется; цепочка рвётся снова, теперь на самом пилоте.
- **Какая работа может его получить:** записать правило «2a — до отъезда, 2b — до конца недели»; чек-лист визита; markdown-шаблон замера; договориться с технологами; пробный визит по методу.
- **Профильные паттерны (слайд 159):** A.3.1 (метод), A.3.2 (описание метода), A.15.2/A.15.5 (план и готовность). Паттерн помогает **оформить** результат, предметный метод (замеры, рационы) — свой.

## Две проверки из практикума

1. **Паттерн ≠ предметный метод:** A.3.1/A.3.2 — оформление; метод про замеры и рационы — предметный, наш.
2. **Выполненная работа никому не приписана:** эскиз method claim ≠ утверждённый метод; «не хватает» — зафиксировано как следующий ход, не как сделанное.
