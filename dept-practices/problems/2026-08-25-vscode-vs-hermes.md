# Проблема: рабочее место экзокортекса — VS Code vs Hermes agent

## Исходная формулировка (дословно)

> «нужно решить стоит ли переходить в работе с экзокортексом с VS code на Hermes agent?»

## Пересказ одним предложением

Проблема в том, что у пилота появился второй канал работы с экзокортексом (Hermes agent, Telegram/CLI), и непонятно, должен ли он сменить VS Code как основное рабочее место или остаться дополнением — от этого зависит, где живут ритуалы и дисциплина записи.

## Зацепка (A.16.1, минимальный пакет)

1. **Ядро наблюдения:** с появлением Hermes agent у работы с экзокортексом стало два рабочих места; вопрос «переходить ли» означает, что текущее разделение ролей между ними не зафиксировано и ощущается как открытое.
2. **Почему стоит не потерять:** основное рабочее место определяет, где исполняются ритуалы (Day Open/Close, WP Gate, скиллы) и дисциплина записи; нерешённый вопрос рабочего места = дрейф практики между двумя инструментами без владельца решения.
3. **Главный свидетель:** формулировка пилота в чате 25.08 (эта сессия). Исходный материал о позиционировании: `AGENTS.md` (корень IWE) — «Hermes НЕ заменяет Claude Code / Kimi Code в кодинге — он координирует, запоминает и даёт мобильный доступ», «Hermes НЕ имеет MCP Gateway (acquire_file_lock / release_file_lock) — правит файлы через terminal + patch».
4. **Контрасты, делающие зацепку узнаваемой:** VS Code — полный инструментарий (файлы, git, MCP Gateway, скиллы, локальные скрипты, ритуалы) vs Hermes — мобильность (Telegram), персистентная память, оркестрация, но усечённый доступ к механике репозиториев. «Переход» (замена) vs «перераспределение» (каждому — своё).
5. **Намёки на направления:** (а) остаться в VS Code как в основном месте, Hermes — мобильный контур и координация; (б) явно перенести в Hermes часть практик (захват заметок с телефона, напоминания, мобильные вопросы к памяти); (в) полный переход на Hermes как основное место.

## Выбор входа

**Вход: сравнение вариантов (C.11/A.19) → ступень выбора**, с короткой проверкой осей сравнения. Принесённое — «что выбрать», варианты названы самой формулировкой (VS Code / Hermes). Карточка проблемы (C.22.2) не является входом; при обнаружении неоформленности осей — возврат к ней легален.

## Различающая проба (B.5.2, 2026-08-25) — по вопросу пилота «как Hermes интегрирован и что даст»

**Паттерны:** B.5.2 (абдуктивная мантра: различающая проба до выбора), A.15 (инструмент-в-роли), DP.D.156 (суть ≠ интерфейс: ядро общее, интерфейсы свои).

Пилот сообщил: для выбора не хватает картины интеграции и преимуществ. Фактура собрана из `exocortex/agent-architecture-framework.md`, `AGENTS.md` (корень IWE), `exocortex/distinctions-warm.md`:

**Как интегрирован сейчас:**
1. Подключён к общему ядру (Aisystant MCP) наравне с другими агентами: видит личную базу знаний, цифровой двойник, когнитивный бриф; может писать заметки и отправлять сообщения в Telegram-бот.
2. Каналы: CLI и Telegram (@aist_me_bot) — работа с телефона, без ноутбука.
3. Правки файлов — только через terminal + patch, без MCP Gateway (блокировок файлов); при конфликте на push — сообщает пилоту.
4. Встроенная автономная память (8 memory-провайдеров рантайма) — его собственность, НЕ источник истины; факты перетекают в ядро через capture с апрувом пилота/экстрактора.
5. Роль зафиксирована (РП-392): оркестратор — координирует агентов, запоминает поручения, даёт мобильный доступ. Кодинг-агентов (Claude Code, Kimi Code) не заменяет.

**Преимущества сверх стека VS Code:**
- Мобильность: работа с экзокортексом из Telegram в командировке/вечером без ноутбука — прямо закрывает наблюдаемый паттерн «нулевые дни в командировках» (WeekReport W34).
- Персистентная память между сессиями из коробки — помнит поручения и разговоры без ритуала восстановления контекста.
- Оркестрация: координация нескольких агентов и напоминания в одном мобильном канале.

**Ограничения (почему не замена):**
- Нет ритуальных скиллов (Day Open/Close, /dept-problem и др. живут локально в `.claude/skills/`).
- Нет блокировок файлов → параллельные правки с другими агентами в одном репо небезопасны.
- Нет локального конвейера (update.sh, календарь, WakaTime, git-операции ритуалов).

**Вывод пробы (кандидат, решение за пилотом):** предмет выбора уточнился — это не «VS Code vs Hermes» (конкуренция за одну роль), а «какие практики закрепить за мобильным контуром Hermes при неизменном основном рабочем месте». Вариант «полный переход» нежизнеспособен по ограничениям выше; содержательная часть вопроса — граница практик Hermes.

## Решение (разовый ответ, ChoiceResult, 2026-08-25 — утверждено пилотом)

**Паттерны:** C.11 (ChoiceResult: chooser — пилот; набор — 3 варианта из зацепки; основание — действующее разделение ролей + ограничения Hermes; правило — дешёвый выход гейта), B.5 (исход «ещё одна проба» для доопределения границы практик).

**Решение:** НЕ переходить. VS Code остаётся основным рабочим местом экзокортекса (ритуалы, скиллы, git, локальный конвейер); Hermes — мобильный контур: захват заметок с телефона (бот → `inbox/fleeting-notes.md` → разбор на Day Open), вопросы к личной базе из Telegram, напоминания.

**Проба (до Week Close W36, 31.08):** использовать три сценария мобильного контура при естественном возникновении (особенно в командировках — закрывают паттерн «нулевые дни», WeekReport W34). На W36 — решить, что закрепить постоянно, что выключить.

**Открытый вопрос (не блокирует решение):** «свой Telegram-канал как вход вместо лички с ботом» — поддержку уточнить у платформы (Aisystant); в локальных документах такой механики не зафиксировано.

**Условие возврата к вопросу «переходить ли» (C.18):** если в пробе ≥ половины взаимодействий с экзокортексом уйдёт в Hermes, или если Hermes получит MCP Gateway и исполнение ритуальных скиллов.

**Сигнал-наблюдение 25.08:** платформа на вызов из сессии Kimi ответила «требуется активная подписка» — проверить соединение/токен ядра (влияет на сценарии мобильного контура).

**Ревьюер записи (Step 3.5):** не запускался — разовая карточка, не архитектурное решение, не ветвь/РП («дешёвая правка — без проверяющего», сем.5). Решение принято пилотом в диалоге 25.08.
