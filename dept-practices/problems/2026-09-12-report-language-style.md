# Карточка проблемы: язык отчётов непрофессиональный

> Маршрут: /dept-problem. Создано на Step 0 (зацепка).

## Исходная формулировка пилота (дословно, 2026-09-12)

> «Мы создавали отчёт. Отчёт сам получился хороший, но мне не нравится язык. Например, там такое слово "тоящийся второй" вместо "тот нужный", "эффект" вместо "экономического" и так далее. Я хотел бы, чтобы язык был более профессиональным. Первая мысль — это создать LPF именно по языковым таким стилям, правилам, словарю и так далее. Запусти dept-problem, и давай этот вопрос разберём — действительно ли это подходит для полного цикла.»

*NB: формулировка получена голосом; примеры искажены распознаванием («тоящийся второй» — не восстановлено). Точные примеры — запросить у пилота со ссылкой на отчёт.*

## Зацепка (A.16.1, минимальный пакет)

1. **Ядро наблюдения:** содержательно хороший отчёт написан непрофессальным языком — неточные слова вместо терминов («эффект» вместо «экономический эффект»).
2. **Почему не потерять:** отчёт — рабочий продукт отдела у клиента; язык несёт доверие к содержанию: небрежная формулировка обесценивает верный расчёт.
3. **Главный свидетель:** итоговый отчёт CASE-002 — `DS-cattle-cases/cases/CASE-002-zencht-leninsky-dynamics/reports/Отчет_ЖК2_итоговый_полный_2026-09-08.md` (принят пилотом 09.09).
4. **Контрасты (дословно из отчёта → как правильно, по пилоту):**
   - «зафиксирована краткосрочная **просадка**» → «краткосрочное **снижение продуктивности**» (жаргон вместо термина с точным предметом);
   - «**держали** мониторинг остатков» → «**производили** мониторинг» (разговорный глагол вместо профессионального);
   - «**денежная оценка эффекта** не приводится» → «**экономическая оценка** не производилась» (неточный термин).
5. **Намёки на направления:** LPF по языку (стили, правила, словарь); альтернативы — готовый внешний стайлгайд, правило вычитки в скилле agro-technologist-report, чек-лист языка в конвейере визит→отчёт.

## Выбранный вход

Карточка проблемы (C.22.2) → Step 1. Обоснование: принесена трудность с одним предположением о решении («создать LPF по языку») — предвыбранную работу проверяет элемент 4 Thin-формы; варианты решения не собраны, поэтому вход не через сравнение вариантов.

### Step 1 — Карточка проблемы (C.22.2, Thin first-use)

**Паттерны:** C.22.2, A.16.1

1. **Сигнал/зацепка** — см. раздел «Зацепка» выше (3 дословных контраста из принятого отчёта CASE-002).
2. **Предмет интереса:** язык (стиль и терминология) итоговых технологических отчётов хозяйствам, производимых конвейером «визит → отчёт» (agro-technologist-report). **Схема отсчёта:** профессиональный русский язык зоотехнической отчётности (термин отрасли + точная канцелярская фраза). **Граница утверждений:** только текст отчётов; содержание, расчёты и выводы — вне предмета (по пилоту, «отчёт сам получился хороший»); другие документы отдела (инструкции, бланки) — пока вне границы.
3. **Семейство утверждения:** факт — три дословных непрофессиональных оборота в отчёте, принятом 09.09; ожидаемое условие — без вмешательства следующий отчёт конвейера воспроизводит те же классы ошибок (пилот: «и так далее»).
4. **Почему не пожелание, не тикет, не предвыбранная работа:** есть наблюдаемый предмет и проба (п.5) — не пожелание; починка трёх фраз в одном файле не закрывает предмет (конвейер воспроизведёт язык в следующем отчёте) — не тикет; «создать LPF по языку» — кандидат-решение, а не вход: проверяется гейтом дешёвых выходов (Step 2) — не предвыбранная работа.
5. **Приёмочная проба (✅ утверждена пилотом 2026-09-12):** в следующем итоговом отчёте хозяйству пилот при приёмке не вносит ни одной языковой правки; три класса ошибок отсутствуют: (а) жаргон вместо термина («просадка» → «снижение продуктивности»), (б) разговорный глагол вместо профессионального («держали» → «производили»), (в) неточный термин («денежная оценка эффекта» → «экономическая оценка»).
6. **Один честный следующий ход:** прогнать гейт дешёвых выходов (Step 2) — проверить, не закрывается ли предмет композицией точных вкладов: эталон E.8/EXD.3 + местный словарь терминов (F.2) + правило вычитки в скилле agro-technologist-report, без создания LPF как продукта.

**Польза клиенту («и что?»):** хозяйство получает документ уровня профессионального консалтинга — формулировки не обесценивают верные расчёты; пилот на приёмке правит содержание, а не язык (время пилота — горлышко конвейера).
