# DPF «Разрывы цикла консультационного визита» — пакет (Reader Guide)

> **Зачем этот этап (простыми словами):** Два паттерна и куча рабочих файлов — это ещё не продукт, это мастерская. Этот файл — «входная дверь»: новый человек открывает его и за минуту понимает, для кого пакет, с чего начать (случился сбой → открой P1), что пакет НЕ делает и когда его надо пересматривать. Если пропустить упаковку, знание останется в головах создателей: новый сотрудник откроет папку, увидит десяток файлов с непонятными номерами и закроет — метод умрёт вместе со сменой людей. Это тот же принцип, что и с кормовой кухней: рецепт на стене работает, только если подписано, для кого, в каком порядке и где лежит.

## Preface — для кого и зачем

**Читатель:** ведущий технолог / руководитель консультационной практики в молочном животноводстве; новый член команды.
**Трудность:** после визита помощника нужное изменение в хозяйстве запаздывает или не происходит; причина всякий раз разная, а чинят «вообще».
**Что даёт пакет:** распознать тип разрыва цикла визита за минуты (P1) и выбрать работу под тип (P2) — без автора пакета.
**Чего пакет не делает:** не оценивает предметные решения (кормление, ветеринария); не заменяет местные регламенты отдела (это LPF, шаг 09); не применяется к задержкам в ожидании данных.

## Refresh Route (G.11) — когда пересматривать пакет

1. Появился 5-й механизм разрыва, не покрытый T1–T4 → переоткрытие архитектуры (successor DRR).
2. Near-miss-разделитель дал ложные срабатывания на переносе (шаг 08) → ремонт P1.
3. P2 при написании тела продублировал CS.METHOD.006/008 → решение о границе DPF ↔ методы отдела.
4. Плановая ревизия — после первых 3 переносов на новые случаи/хозяйства.
