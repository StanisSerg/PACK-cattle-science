# P2 · Замкни цикл визита (Solution)

> **Зачем этот этап (простыми словами):** Поставить диагноз и не назначить лечение — деньги на ветеринара впустую. Этот файл — вторая половина пары: на каждый тип разрыва из P1 своя работа, потому что «пишите быстрее» не вылечит помощника, который пропустил половину аудита, а красивый отчёт не спасёт новость, сообщённую вскользь. Если пропустить это разделение, все сбои начнут лечить одним любимым средством — обычно «написать регламент получше» — и удивляться, что не помогает. Здесь же честная граница: метод называет ВИДЫ работ, а конкретные формы (списки, окна, пороги) остаются местным делом отдела — это шаг 09, без него паттерн не превратится в регламент.

> Часть DPF «Разрывы цикла консультационного визита». Вход — строка фиксации из P1: «разрыв T<N> в звене <звено>, свидетельство: …».
> P2 отвечает на вопрос: **какую работу делать под этот тип разрыва.** Без типа из P1 работы не выбирать.

## Узнаваемое начало

Тип разрыва известен (P1 применён). Искушение — «написать регламент получше». Стоп: работа зависит от типа. Ускорение канала не лечит «вскользь»; красивый отчёт не лечит пропущенные шаги аудита.

**Что сделать сначала (пр.5 сл.59):** проверить, что тип разрыва назван в P1 со свидетельством (строка фиксации «разрыв T<N> в звене <звено>, свидетельство: …»). Нет строки фиксации — назад в P1, работу не выбирать.

## Solution

### T1 · Время → **допуск по цене ошибки + лёгкий сигнал**

Разрыв по времени лечится не «писать быстрее», а переносом действия в точку визита:
1. Каждое «моментное» изменение заранее отнесено к классу: **«делай сам» / «только с подтверждением»**. Класс = цена ошибки действия (дорогая ошибка → подтверждение).
2. После визита — **лёгкий сигнал ≤2–3 минут**: «визит был / сделал сам: … / ждёт подтверждения: …». Подробности — отдельно, в тот же день.
3. Готовая реализация: **метод B** (full-cycle, `docs/fpf/FPF_practical/full-cycle/05-method-claim.md`) — список допуска D1, карточка сигнала D2, правило подтверждений D3 — местные формы, шаг 09 (LPF).

### T2 · Форма → **форма носителя + read-back на эскалациях**

1. Рабочая форма сообщения: короткий структурированный текст (не голосовое 40 минут, не сырой транскрипт). Норма HHPM: **точка «done» визита = внесение данных в систему**, не факт осмотра и не «отправил».
2. **Read-back — только для дорогих действий:** получатель подтверждения повторяет суть («подтверждаю: переставляем 20 коров в группу Б»), отправитель фиксирует. На рутине read-back запрещён — шум съест внимание (разрешение противоречия «фильтрация vs дублирование», 04-drr.md).
3. Если источник — сырой носитель (аудио/транскрипт): отдельная работа «восстановление рабочей картины» (пример: практика С4-П8 по Битимскому) — до решения, не после.

### T3 · Приоритет → **эскалационное кадрирование**

1. Форма эскалации (SBAR-подобная, 3 строки): **«Что случилось / чем грозит / что предлагаю до <срока>»**. Эскалация визуально отлична от рутины (маркер ❗ в общем чате — минимум).
2. Правило канала: существенное **не пишется в ряд рутинных сообщений** — отдельным сообщением с маркером.
3. Ведущий обязан подтвердить приём эскалации в согласованное окно (окно — местное, шаг 09); тишина за окном — эскалация повторяется/поднимается (правило эскалации — местное).
4. Порог «что существенно» калибруется на данных отдела (шаг 09), не назначается «с потолка».

### T4 · Полнота → **чек-лист полноты визита**

1. Чек-лист шагов визита — наследует **CS.METHOD.006** (сбор → верификация model vs reality → WorkPlan с ответственным, сроком, проверкой). Не дублировать метод — сослаться и местно адаптировать (шаг 09).
2. Пункты — **состояния с записью**, не глаголы: «замеры внесены в таблицу — да/нет», не «провести замеры» (методика R7; ложный ✅ — практика С4-П4).
3. **Правило вывода (усиление по случаю шага 08):** заключение «в норме» допустимо только при закрытом чек-листе полноты; без него доклад обязан называться **«данных недостаточно»**. Ложно-успокоительный доклад опаснее отсутствия доклада.
4. **Оговорка Онтарио:** чек-лист без внедрения не работает (при 95% формальной комплаентности эффект нулевой). Обязательны: обучение на месте, 5–9 повторений, контроль использования — это работа LPF (шаг 09), не текст паттерна.

## Границы

- Работы применяются **только по типу из P1**; «что-то не так» без типа → назад в P1.
- P2 называет работы и их типы; **местные формы** (список допуска, окна, пороги, формуляры) — LPF отдела, шаг 09. Пороги допуска здесь не заданы — это не пробел, а граница DPF/LPF.
- P2 не оценивает предметную правильность изменений (кормление, ветеринария) — только своевременность и состоятельность цикла.
- «Цикл цел» (near-miss из P1) — работ не требует; ожидание анализов чинить не надо.

**Связка выборов с SoTA (пр.5 сл.59, добавлено по сверке 23.08):** «допуск по цене ошибки» (T1) опирается на MBE/пороговую фильтрацию (SoTA линия 3, `03-sota.md`); «точка done = внесение данных» (T2) — на HHPM (линия 1, [ISAH 2007](https://www.isah-soc.org/userfiles/downloads/proceedings/Proc_ISAH_2007_Volume_I/01_Noordhuizen.pdf)) и CS.METHOD.008; «эскалационное кадрирование» (T3) — на SBAR (линия 2, [Shahid 2018](https://d-nb.info/1168090792/34)); «чек-лист полноты» (T4) — на чек-листы WHO с оговоркой Онтарио (линия 2, NEJM 2009).
