# 00 — Гейт нужности: цикл визита помощника

> **Зачем этот этап (простыми словами):** Прежде чем неделями писать «методику», честно отвечаем: а нельзя ли закрыть проблему дешевле — взять готовое, один раз ответить или вообще смириться. Если этот шаг пропустить, получится красивый документ, ради которого никто не будет менять работу: трудность-то была разовая или уже решена чужим трудом. Здесь же фиксируется, чего именно не хватает — переносимого способа, который сработает в следующем хозяйстве без сборки с нуля. Без этой фиксации все следующие шаги повисают в воздухе: непонятно, что именно строим.

> Форма практики 1: общее различение / переносимый способ / местная практика / использование результата / первичный дефицит + проверочное наблюдение.

## Трудность и нужный результат (шаг 01)

**Трудность:** консультационная практика — визиты помощников в хозяйства; изменения, требуемые в день визита, не выполняются в день визита, потому что цепочка «визит → информация у ведущего → действие» разрывается по времени. Каждый раз (новое хозяйство, новый помощник) способ решения собирается заново.

**Нужный результат:** переносимый способ распознавать разрывы цикла визита и выбирать работу по их устранению — пригодный для повторного применения в новом хозяйстве без пересборки различений.

**Получатель результата и для какого решения/работы он нужен (сем.5 сл.22):** ведущий технолог — для решения «какую работу выбрать под тип разрыва» (диагностика → работа) и для ревизии списка допуска; новый помощник / новое хозяйство — для работы входа по готовым различениям без автора. Смена получателя меняет состав фреймворка — поэтому получатель зафиксирован здесь явно.

**Источник-задел:** full-cycle (2026-08-02): карточка проблемы (`01-problem-card.md`), method claim метода B (`05-method-claim.md`), разбор потоков и разрыва 4→5 (`../../docs/fpf/FPF_practical/seminar-03/2026-08-01-practice-5-earliest-broken-transition.md`).

## Пять строк (практика 1)

1. **Общее различение:** информационный разрыв (ведущий узнаёт поздно) ≠ разрыв полномочий (помощник на месте без права действовать) — разные классы методов; смешение двух разрывов в одно «плохо пишут» — главная ошибка.
2. **Переносимый способ (кандидат в DPF):** гранулированный допуск по цене ошибки действия («делай сам» / «с подтверждением») + лёгкий сигнал «сразу коротко, подробности позже в тот же день».
3. **Местная практика (кандидат в LPF отдела):** конкретный список допуска D1, форма сигнала в Telegram, окно ответа ведущего, пороги способностей помощников, персонал конкретных хозяйств.
4. **Использование результата:** новый помощник/хозяйство входит в работу по готовым различениям; ведущий ревизует список допуска, а не собирает метод с нуля.
5. **Первичный дефицит:** предметный метод для одного хозяйства есть (метод B, full-cycle) — дефицит в **переносимости**: различения и основания выбора живут в записях одного кейса и не оформлены как знание, пригодное к переносу. Дефицит класса: **DPF** (ядро) + **LPF** (местная обвязка). Не FPF (паттерны есть), не «не нужен» (трудность повторяется).

**Проверочное наблюдение:** ближайшее новое хозяйство или новый помощник. Если для входа придётся заново объяснять «что существенно, какие альтернативы, где граница применения» — дефицит подтверждён; если различения переносятся — DPF работает.

## Дешёвые выходы (проверены до авторства)

| Выход | Вердикт |
|---|---|
| Применить готовый FPF | Не закрывает: FPF даёт паттерны работы (C.22.2, A.3.1), не предметные различения цикла визита |
| Применить существующий DPF | Нет DPF по консультационным визитам в животноводстве (SoTA-шаг 03 проверит) |
| Тонкий маршрут к источникам | Не закрывает: статьи не дают способа распознавания разрывов и выбора работы |
| Инструмент (сем.5 сл.20 — добавлено по сверке 23.08) | Не закрывает: инструмент (чат, форма, напоминалка) исполняет способ, но не задаёт различения типов разрыва; без способа инструмент закрепит текущую практику |
| Один разовый ответ | Уже состоялся (метод B для одного хозяйства) — трудность повторяется, разового ответа мало |
| Честная остановка | Не обоснована: трудность повторяющаяся, цена разрыва — несделанные изменения на ферме |

**Анти-паттерн гейта** (сем.5 сл.20): если нужный паттерн уже принят, но сотрудники его не находят — первичный дефицит относится к **доступу или маршруту**, а не к новому DPF. Местное правило доступа к данным также не становится законом всей области.

**Правило возврата** (сем.5 сл.20): если сейчас нужен только один проверяемый ответ — весь DPF не начинают; гипотезу о повторяемости трудности сохраняют и возвращаются к ней **после второго различающегося случая**. (Здесь не применено: случаев четыре, см. `02-cases.md`.)

**Вердикт гейта:** дешёвые выходы не закрывают трудность → маршрут создания DPF/LPF оправдан. Следующий шаг: 02 — три различающихся случая + общий вопрос + near-miss.

## Кандидаты в корпус случаев (к шагу 02)

1. Хозяйство РБ (основной кейс full-cycle, 2 помощника, Telegram).
2. СХПК Битимский — транскрипт визита (DS-plaud), использован в практике С4-П8.
3. Третий случай — **вход от пилота** (другое хозяйство/визит, где цикл сработал иначе или не сработал).
4. Near-miss контрпример — **вход от пилота**: случай, похожий на разрыв цикла, но им не являющийся (например: изменение сознательно отложено по предметным причинам — задержка была правильной).
