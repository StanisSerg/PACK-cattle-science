# LPF отдела · Цикл визита (местная практика)

> **Зачем этот этап (простыми словами):** Общий метод (DPF) говорит «что делать вообще», но не отвечает на бытовые вопросы вашего отдела: в каком чате писать, до которого часа ждать ответ ведущего, что конкретно помощнику можно делать самому на ваших фермах, какие пункты в чек-листе аудита. Этот файл — перевод общего метода на местный язык: роли поимённо, формы сообщений, пороги «что существенно», цифры, по которым через месяц видно, работает или нет. Если пропустить этот этап, паттерн останется красивой теорией в папке: помощник не узнает, что именно от него изменилось в понедельник. Метки **[П]** — места, где решение может принять только пилот: он знает свои хозяйства и людей.

> Один DPF — много LPF. Здесь — воспроизводимая местная практика: роли, формы, окна, данные, проверка, остановка.
> Из DPF берём типологию (P1) и типы работ (P2) по значению; всё конкретное — местное.

## 1. Роли и среда

| Роль | Кто | Инструмент |
|---|---|---|
| Ведущий технолог | пилот | Telegram, этот репо |
| Помощники | 2 чел. | Telegram |
| Персонал ферм | по хозяйствам | устные указания помощника в рамках допуска |

Канал: Telegram (общий чат + ❗-эскалации). Данные о ходе работы: сообщения-сигналы, чек-листы, таблица замеров.

## 2. Местные формы по типам разрыва (наследие P2)

**T1 · Допуск и сигнал (метод B):**
- D1 — список допуска «делай сам / с подтверждением» по цене ошибки: **[П] содержимое — пилот** (знает хозяйства).
- D2 — карточка сигнала (≤2–3 мин): «визит был / сделал сам: … / ждёт подтверждения: …» — кандидат, утвердить **[П]**.
- D3 — правило подтверждений: окно ответа ведущего **[П: какой час?]**, при тишине — **[П: безопасный вариант / повторный сигнал?]**.
- Пороги способностей помощников: полный допуск сразу или поэтапно **[П]**.

**T2 · Форма носителя:**
- Рабочая форма — короткий структурированный текст; голосовые >3 мин и сырые транскрипты — не рабочая форма (только через восстановление картины).
- Read-back обязателен для действий из класса «с подтверждением»; на рутине запрещён.
- Норма: визит «done» = данные внесены, не «написал в чат» (CS.METHOD.008).

**T3 · Эскалация:**
- Форма 3 строки: «Что случилось / чем грозит / что предлагаю до <срок>» — отдельным сообщением с ❗, не в хвосте отчёта.
- Окно приёма эскалации ведущим **[П: окно?]**; тишина за окном → повтор + звонок.
- Порог «существенно» — стартовая версия: риск здоровью коровы, падение молока >X кг/день **[П: X]**, сбой кормления; калибровка на данных через 4 недели.

**T4 · Чек-лист полноты визита** (наследует CS.METHOD.006):
- Состав пунктов под аудит кормления **[П: совместно дописать по CS.METHOD.006]**: остатки стола взвешены/внесены, пробы отобраны/промаркированы, траншея осмотрена, температура силоса измерена, THI зафиксирован (не «жара» ссылкой).
- **Правило вывода:** без закрытого чек-листа доклад = «данных недостаточно». «В норме» — только при полном чек-листе.

## 3. Несводимые характеристики (3–5) с нижними границами

| Характеристика | Нижняя граница | Свидетельство |
|---|---|---|
| Доля визитов с изменениями в день визита | ≥ [П: старт 50%?] → рост за 4–6 недель | таблица визитов |
| Медианное время «визит → изменение» | ≤ 1 день | метки сигналов |
| Эскалации с ответом в окне | 100% (иначе окно нереально) | ❗-сообщения |
| Визиты с полным чек-листом | ≥ 90% через месяц внедрения | чек-листы |
| Докладов «в норме» без полноты | **0** | выборочная сверка ведущим |

## 4. Проверка и внедрение (Онтарио-предупреждение)

- Обучение: одна встреча-инструктаж + **5–9 повторений** на реальных визитах; первые 2 недели — ежедневная сверка формы сигналов.
- Контроль использования: ведущий спрашивает по чек-листам каждую неделю (ритм «сержанта»); не пользуются — разбор, не угроза.
- Проверка LPF целиком: через 4–6 недель пилота метода B — характеристики из §3 против базовой линии **[П: замер базовой линии — вход из WP-111]**.

## 5. Условия остановки и восстановления

- **Остановка (honest stop, метод B):** 4–6 недель без роста доли своевременных изменений → диагностика: метод / выполнение / причинная гипотеза. Не «усиливать» автоматически.
- **Восстановление конфигурации:** текущая форма каждого артефакта (D1–D4, чек-листы, пороги) живёт в `dept-practices/`; версия и дата на каждом; откат — к прошлой редакции файла.
- **Обращение к человеку:** любой случай «предметная эскалация» из P1 (ожидание данных > предметного окна) — немедленно к ведущему, не по чек-листу.

## 6. Местная мантра

> «Сигнал сразу, подробности до конца дня; "в норме" — только с полным чек-листом; существенное — с ❗, не в хвосте».
