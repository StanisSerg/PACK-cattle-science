# P1 · Распознай разрыв цикла визита (Solution)

> Часть DPF «Разрывы цикла консультационного визита». Пара: P2 «Замкни цикл визита» (работа по типу разрыва).
> Применять, когда решение по хозяйству запоздало или не состоялось после визита — и неясно, где порвалась цепочка.

## Узнаваемое начало (recognition)

Помощник (консультант, полевой специалист) был в хозяйстве. Через дни выясняется: нужное изменение не сделано или сделано поздно. Все помнят, что «он туда ездил» и «что-то писал в чат». Вопрос — **где именно порвалась цепочка** «визит → информация у ведущего → действие в нужный день»: визит состоялся, а результата нет.

## Solution

### Шаг 1. Проверь near-miss (разделитель — до диагностики)

Спроси: **«Изменение отложено в ожидании данных?»** (анализы кормов, лаборатория, расчёты — частая практика).
- Нет → шаг 2.
- Да → второй вопрос: **«Срок ожидания данных короче окна, в которое изменение ещё полезно?»**
  - Да → **цикл цел**, задержка предметная; паттерн неприменим. Стоп.
  - Нет / неизвестно → это не разрыв цикла, но и не «стоп»: выход **«предметная эскалация»** — ожидание данных длиннее предметного окна (пример: переходный период не ждёт неделю анализов). Немедленно к ведущему по форме эскалации из P2-T3. Дальше по P1 не идти.

### Шаг 2. Распознай тип разрыва по наблюдениям

| Тип | Наблюдения-признаки | Из корпуса |
|---|---|---|
| **T1 · Время** | Сообщение о визите пришло на следующий день или позже; вопросы ведущего остались без ответа в день визита; изменение сделано «задним числом» | Хозяйство РБ |
| **T2 · Форма** | Информация есть, но использовать её для решения нельзя: сырой транскрипт, голосовые без структуры, фото без подписей; чтобы понять — нужна ручная расшифровка | СХПК Битимский |

> **Разделитель T1/T2:** если сообщение пришло вовремя, но *использовать* его для решения в тот же день нельзя (40-минутное голосовое, сырой транскрипт) — это T2, не T1: форма виновата в задержке. Тест: «с рабочей формой решение приняли бы в день визита?» Да → T2.
| **T3 · Приоритет** | Существенное сообщено «вскользь», в одном ряду с рутиной; у получателя нет способа отличить критичное от фонового; о важности узнали по последствиям (падение молока) | Случай «вскользь» |
| **T4 · Полнота** | Визит состоялся, но часть шагов пропущена; обнаруживается по нехватке данных для решения; нужен повторный выезд | Неполный аудит |

Одна цепочка может содержать несколько разрывов — называй **самый ранний** (он блокирует остальные).

### Шаг 3. Зафиксируй результат

Результат применения P1 — одна строка: **«разрыв типа T<N> в звене <звено>, свидетельство: <наблюдение>»** или **«цикл цел»** (near-miss).

**Звенья цепочки** (имена зафиксированы, другие не изобретать): `визит` (выполнение на месте) · `сообщение` (передача информации) · `информация у ведущего` (приём и понимание) · `действие на ферме` (выполнение изменения).

Примеры: «разрыв типа T2 в звене "сообщение", свидетельство: 40-минутное голосовое без структуры» · «разрыв типа T3 в звене "сообщение", свидетельство: кетоз сообщён в хвосте рутинного отчёта без маркера».

Этого достаточно для входа в P2 (выбор работы). Если тип не распознаётся по доступным наблюдениям — честная остановка: список, каких наблюдений не хватает, а не догадка.

## Границы

- P1 — только диагностика. Работы по устранению — P2; применять работы без типа разрыва — ошибка (SBAR от приоритета не лечит неполный аудит).
- Типология эмпирически не валидирована (конструкт корпуса из 4 случаев); 5-й механизм → переоткрытие архитектуры (см. `04-drr.md`).
- Задержки в ожидании данных — не разрыв (near-miss, шаг 1).
- P1 не оценивает качество самих предметных решений (кормление, ветеринария) — только целостность цепочки.
